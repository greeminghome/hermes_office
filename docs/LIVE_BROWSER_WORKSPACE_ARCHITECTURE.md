# Live Browser 작업공간 아키텍처

## 목표

각 구성원과 각 대화 세션이 서로 독립된 Chrome 작업공간을 사용하면서, 한 작업공간의 여러 탭을 Live Screen에서 빠르게 확인하고 직접 조작할 수 있게 한다.

## 격리 모델

`구성원 프로필 → Hermes 대화 세션 → Chrome BrowserContext → 페이지 탭`

- 프로필별 CDP 라우터만 사용하며 다른 구성원의 Chrome으로 폴백하지 않는다.
- 공개 스키마에서 세션 ID를 생략하는 `browser_cdp` 호출도 현재 Hermes 대화의 durable session ID를 자동으로 사용한다.
- 새 대화와 분기 대화는 새 BrowserContext를 사용한다.
- 자동 컨텍스트 압축으로 대화 ID가 교체될 때만 기존 브라우저 작업공간 ID를 계승한다.
- Office는 라우터가 확인해 준 해당 BrowserContext의 탭만 표시한다.

## 사용자 경험

- 탭은 긴 사이트 이름 대신 안정적인 번호 `1, 2, 3…`으로 표시한다.
- 번호 바는 가로 스크롤/스와이프되며 원격 화면 자체의 스와이프와 분리한다.
- 기본값은 `구성원 따라가기`이다. 구성원이 활성화한 탭이 바뀌면 Live Screen도 같은 탭으로 이동한다.
- 사용자가 번호를 직접 선택하면 그 화면을 고정한다.
- 고정 화면과 구성원의 활성 탭이 다를 때만 `구성원 화면으로` 버튼을 표시한다.
- 모바일에서는 채팅 헤더의 Live 버튼으로 전체 화면 뷰어를 열고 같은 탭 정책을 사용한다.

## 탭 수명과 부하 정책

- 표시 권장 한도는 10개, 안전 한도는 16개이다.
- 안전 한도를 넘는 새 탭 생성은 거부하되 기존 탭을 자동으로 닫지 않는다.
- 24시간 동안 작업이 없는 페이지는 닫을 수 있지만 BrowserContext는 30일 보존한다.
- 실제 화면 스트림은 인라인 패널, 전체 화면 또는 독립 뷰어가 열렸을 때만 생성한다.
- 목록 동기화는 가벼운 메타데이터 요청으로 처리하고, 프레임은 선택된 한 탭만 중계한다.

## 장애 처리

- 매핑이 아직 없으면 무한 로딩 대신 `브라우저 작업 대기` 상태와 이유를 표시한다.
- 마지막 정상 프레임은 같은 탭의 일시적 재연결 동안 유지한다.
- 유효하지 않거나 다른 세션의 targetId는 서버와 CDP 라우터 양쪽에서 거부한다.
- 기존 프로필의 미분류 Chrome 탭은 임의로 현재 세션에 편입하거나 닫지 않는다.

## 단계별 완료 기준

1. 라우팅: `browser_cdp`와 일반 browser 도구가 동일한 세션 라우터를 사용한다.
2. 격리: 같은 구성원의 서로 다른 세션이 서로의 targetId를 조회하거나 연결하지 못한다.
3. 다중 탭: 세션 내 모든 페이지가 안정적인 번호와 활성 상태로 반환된다.
4. UI: 데스크톱·태블릿·모바일에서 번호 선택, 가로 스크롤, 따라가기 복귀가 동작한다.
5. 회귀: 채팅, 4K 스트림, 입력 제어권, 전체 화면, 세션 종료 정리가 기존 테스트를 통과한다.
6. 운영: 배포 후 실제 Office에서 데스크톱과 모바일 뷰포트를 검증하고 오류 로그를 감사한다.

## 운영 전수 감사

컨테이너 안에서 `node /usr/local/bin/audit-browser-profile-isolation.mjs`를 실행한다.

- `HERMES_GATEWAY_PROFILES`의 모든 구성원과 기본 브라우저 경로를 검사한다.
- 프로필마다 두 개의 임시 BrowserContext를 만들어 세션 간 탭 목록과 attach/activate/close 권한이 분리되는지 확인한다.
- 한 프로필의 임시 세션이 다른 모든 프로필 라우터에서 보이지 않는지 교차 검사한다.
- 감사가 성공하거나 실패해도 임시 BrowserContext를 제거하고, 제거 후 수동 조회가 404인지 재확인한다.
- 기존 세션, 로그인 탭, 사용자 브라우저 데이터는 감사 대상으로 열거나 변경하지 않는다.

이어서 `python3 /usr/local/bin/audit-browser-session-ownership.py`를 실행한다. 각 프로필 DB, 영구 소유권 레코드, BrowserContext 상태 파일과 압축 세션 별칭을 대조해 동일한 세션이 둘 이상의 프로필 라우터에 남아 있거나 다른 프로필 작업공간을 계승하는 오류를 탐지한다. 이 감사도 읽기 전용이다.

Office 컨테이너에서는 `node /app/deploy/scripts/audit-live-screen-profile-routes.mjs`를 실행한다. 구성된 모든 프로필 라우터에 임시 작업공간을 만들고 Office 중계가 자기 프로필에는 뷰어 티켓을 발급하면서 다른 프로필의 같은 세션은 노출하지 않는지 검사한다. durable session ID와 browser workspace ID가 다른 요청도 400으로 거부되는지 확인하며, 임시 작업공간은 항상 제거한다.
