프로필 Chrome은 감독 루프가 미리 준비할 수 있다. 세션 BrowserContext는 첫 브라우저 사용 시 생성된다.
새 구성원을 추가하는 것과 무관하게 각 대화의 페이지는 독립되며, 기존 미분류 탭을 임의 편입하지 않는다.

## 발견한 문제와 수정

- 탭이 하나면 번호 바가 사라지고, 프레임이 없으면 작업공간 탭도 숨겨졌음 → 번호 바를 작업공간 기준으로 표시.
- 저장된 세션의 과거 브라우저 이벤트가 없거나 첫 조회가 실패하면 대기 상태가 지속됨 → 수동 생성 없는 재발견과 재조회.
- 프로필 목록 갱신으로 선택 구성원이 초기값으로 돌아갈 수 있었음 → 안정적인 프로필 ID로 effect 의존성을 제한.
- 연결 종료가 세션 종료로 취급돼 BrowserContext가 삭제됨 → 명시적 종료·삭제·보관과 전송 계층 정리를 분리.
- 새 구성원은 고정 목록 밖에 있어 UI/도구/서버 라우팅이 불일치 → 공통 영구 런타임 레지스트리 적용.
- 선택 탭과 직전 프레임이 잠시 불일치할 수 있었음 → target 일치 확인 후 렌더링.
- 손상된 프로필 레지스트리가 슬롯 재배정으로 이어질 위험 → 파일을 덮어쓰지 않고 실패 처리.

## 검증 증거

- 데스크톱·390px 모바일에서 번호 탭, 빈 탭 대기, 선택 화면 하나, 따라가기 복귀 확인.
- 모바일 12개 탭 가로 스크롤: body 폭 390px 유지, 마지막 탭 접근 가능.
- 원격 입력: 테스트 input 값 `live-browser-ok`, 버튼 클릭 1회, 스크롤 위치 800px를 서버에서 읽어 검증.
- 모바일 실제 채팅의 Live 모달: 모달 1개, 탭 1개, canvas 1개.
- Agent 격리: 기본 런타임 포함 10개 프로필, 임시 컨텍스트 20개, 교차 조회 90개 차단, 타 세션 대상 조작 30개 차단.
- Office 격리: 구성원 9명 자기 라우팅, 교차 조회 72개 차단, 세션 결합 불일치 거부.
- 세션 소유권 감사: issues 없음. 감사용 컨텍스트는 정리 완료.
- Python 실제 함수 추출 테스트: 7/7 통과. 전송 종료 보존과 명시적 종료 폐기를 별도 검사.

## 범위와 한계

실제 예약 생성·취소, 로그인 정보, 판매 채널 설정은 변경하지 않았다.
